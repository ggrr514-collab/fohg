# ディベート振り返り Web App (Google Apps Script)

スプレッドシートをデータベースにした、授業用のディベート進行アプリです。
`Code.gs`(サーバ)と `index.html`(画面)の2ファイルを Apps Script プロジェクトに置いて使います。

## 今回の変更点(フェーズ3.0)

### 1. 教員ビュー / 生徒ビューの統合

教員も生徒と **まったく同じ画面** を見ます。教員アカウントのときだけ、画面下部に操作バーが重なります。

- 「生徒として見る / 教員ビューに戻る」の切替は廃止しました
- 操作バーには、そのフェーズで次にやること **1つだけ** が主ボタンとして出ます
  (くじを引く準備 → ルーレットを回す → 投票受付を開始 → 投票を締切 → 勝敗を発表 →
   GD発表へ → 第5位・第4位を発表 → まとめ受付を開始 → 全員強制提出)
- クラスの切替は操作バー左のプルダウンから。「⋯ その他」を開くと、待機中に戻す・くじ履歴リセット・
  まとめ受付を締切・フェーズの直接変更・全クラスの状況一覧が出ます
- 「操作バーを隠す(投影用)」で、教員機を黒板に映しても操作ボタンが映り込みません
  (右下の ⚙ ボタンで戻せます)
- ルーレットは生徒機にも同じように出ます
- **勝敗発表・グッドディベーター発表は教員の画面にだけ出ます**。通信のずれで生徒の手元に
  先に結果が出ると発表がぐだぐだになるため、画面に出さないだけでなく、集計データ自体を
  生徒の端末に送りません(サーバ側で `results` を教員にしか渡さない)。
  生徒の手元には「先生の画面(スクリーン)を見てください」とだけ表示されます
- 教員も投票できます(勝敗票は3票換算。GDの集計には入りません)
- まとめ受付中は、教員には生徒と同じフォームが読み取り専用で表示されます

### 2. 画面切り替えの遅れの解消

- **「画面を更新」ボタンを廃止**。フェーズが変わると生徒の画面は自動で切り替わります
  (以前は全員がボタンを押す必要があり、これが最大の待ち時間でした)
- ポーリングを `pollState()` の **1往復** に統合。変化を検知したときは、同じレスポンスに
  次の画面のデータを載せて返します(以前は「変化検知」と「画面データ取得」で2往復)
- `CacheService` による共有キャッシュを追加。名簿・班マスタ・論題・発表者・状態・集計を
  短時間キャッシュし、30人が同時にポーリングしてもスプレッドシート読み取りが増えません
- 状態の書き込みをバッチ化。くじ確定など複数キーを書く操作が、シート1往復で済みます
- ポーリング間隔をフェーズに応じて調整(待機中6秒 / 進行中2.5秒 / カウントダウン中1.5秒)。
  通信失敗時は自動で間隔を空けて再試行し、切り替えボタンではなく細い進行バーで更新を知らせます
- まとめ受付中 ⇄ 強制提出カウント中 の遷移では画面を描き直さないので、
  **生徒が入力途中のテキストや変換中の文字が消えません**
- 強制提出の残り時間はサーバから「残りミリ秒」で受け取ります。端末の時計がずれていても正しく数えます

## 使い方

1. スプレッドシートで「ディベートアプリ → 初期セットアップ」を実行
2. 名簿・班マスタ・論題マスタを埋める
3. Web アプリとしてデプロイ(**アクセスするユーザーとして実行**)
4. 教員アカウントでURLを開き、画面下部の操作バーから進行する

シートを手作業で直したあとに反映が遅い場合は、メニューの
「シートを手で直した後のキャッシュ消去」を実行してください
(アプリからの操作は常に即時反映されます)。

## シート構成

| シート | 列 |
| --- | --- |
| 名簿 | A:クラス B:番号 C:氏名 D:メール E:役割(生徒/教員) |
| 班マスタ | 名簿のA〜E + F:班番号 G:ディベート役割 |
| 論題マスタ | A:論題ID B:論題文 C:実施日 **D・E:その論題を担当する2つの班** F:対象クラス G:備考 |
| 発表者マスタ | 論題ID/メール/氏名/組/番/班/役割/表示順(くじ確定時に自動生成) |
| 投票 | 日時/論題ID/投票者/氏名/組/番/勝敗/GD1〜GD5 |
| まとめ | …/M:確認済み N:評価 O:違反ロック P:違反詳細 |
| 状態管理 | A:クラス B:キー C:値(クラスごとに独立して進行できます) |

## くじが引けないとき

「ルーレットを回す」を押しても数字が出ない場合、画面に **理由** が出ます。
候補が0件になる原因は次の3つのどれかです。

| 画面の表示 | 原因 | 直し方 |
| --- | --- | --- |
| 論題マスタに、対象クラスが「○○」の論題が1件もありません | 論題マスタのF列(対象クラス)が、班マスタのクラス名と一致していない/空欄 | F列を班マスタのクラス名と同じ表記にする。画面に「論題マスタのF列に今ある値」が一覧で出ます |
| 担当班(D列・E列)から班番号を読み取れませんでした | 論題マスタのD列・E列が空欄、または数字になっていない | 担当する2つの班番号を半角数字で入れる。メニュー「ディベートアプリ → 論題マスタの担当班(D・E列)を自動で割り当て」で仮置きもできます |
| このクラスのディベートはすべて終了しました(全N班分) | 本当に全部引き終わった | 操作バーの「その他 → くじ履歴をリセット」 |

表記ゆれは吸収します。クラス名の全角/半角・空白の違い、班番号の `1` `１` `1班` `第1班` は
同じものとして扱われます。また「ルーレットを回す」を押すたびに論題マスタ・班マスタを
読み直すので、**シートを直してそのまま押し直せば反映されます**(キャッシュ消去は不要)。

## くじの仕組み

1. くじで、そのクラスの班番号からランダムに1つ選ぶ(使用済みの班は出ません)
2. **出た番号の班が肯定側**、論題マスタでその班と組になっている**もう一方の班が否定側**
3. 担当する論題も自動で決まる

論題マスタのD列・E列は「その論題を担当する2つの班」です。
**どちらが肯定側になるかはくじで決まる**ので、D列とE列の順番に意味はありません
(元シートの見出しが「A」「B」なのはこのためで、アプリも書き換えません)。

くじ準備中の画面には、教員にだけ「この組の論題と担当班」の対応表が出ます。
回す前に、準備してある担当と合っているか確認してください。

### 担当班の自動割り当て(仮置き)

D列・E列が空欄だと、くじの候補が作れません。メニュー
「ディベートアプリ → 論題マスタの担当班(D・E列)を自動で割り当て」で、
班マスタの班番号をクラスごとに論題の並び順で2つずつ入れられます。

例: 1クラスに6班・論題3件 → 1論題目 1班と2班 / 2論題目 3班と4班 / 3論題目 5班と6班

- **これは機械的な仮置きです。** 実際の担当が別の組み合わせなら、実行後にD列・E列を手で直してください
- 実行前に「何をどう埋めるか」を確認ダイアログで表示します
- **空欄の行だけ**を埋めます。既に入っている値も見出しも変更しません

## コードを更新したあとの反映

Apps Script のウェブアプリは、エディタでコードを貼り替えただけでは公開URLに反映されません。

1. Apps Script エディタで `Code.gs` と `index.html` を丸ごと置き換えて保存
2. 右上「デプロイ」→「**デプロイを管理**」
3. 使っているデプロイの鉛筆(編集)アイコン → バージョンを「**新バージョン**」に → 「デプロイ」

これで同じURLのまま新しいコードになります。「新しいデプロイ」を選ぶとURLが変わるので注意してください。

## グッドディベーターが「該当者がいません」になるとき

グッドディベーターは **生徒の票だけ** で集計します(教員の票は勝敗のみ3票換算で反映)。
そのため教員だけで通しテストすると必ず0件になります。
画面には投票の内訳(総数・生徒・教員)と理由が出るので、それで判断してください。
